# CT-OS T0 / 持仓路径 / 个股 AI 作战档案方案

> 日期：2026-06-03  
> 定位：当前是交易教练；长期目标是受控交易机器人。  
> 边界：本方案第一阶段只做纸盘、动作草案、状态展示和 AI 解释，不接真实自动下单。

## 1. 核心目标

CT-OS 下一阶段不是继续把 AI 做成泛泛的问答器，而是把系统升级为“路径驱动的交易机器人前置系统”。

核心变化：

- 从“完全分类解释”升级为“买卖点转化路径推演”
- 从“关注某个价格”升级为“当前处于哪个结构任务，下一步等什么确认”
- 从“一次性 AI 问答”升级为“每只股票有长期作战档案”
- 从“买完等涨跌”升级为“核心持仓生命周期管理”
- 从“教练建议”逐步走向“动作草案、纸盘验证、受控执行”

一句话：

> 大周期路径引擎决定战略方向，T0 状态机处理盘中节奏，个股 AI 作战档案记住这只票的历史，资金管理决定能不能动、动多少。

## 1.1 核心持仓生命周期

CT-OS 的目标不是大范围追很多股票，而是深度陪跑少数有潜力的核心标的，吃完整走势周期。

有潜力的票不能“买完就等它涨，跌破就止损”。正确路径应该是：

```text
选中核心标的
  ↓
试探建仓
  ↓
建仓后验证
  ↓
盘中做T降低成本 / 缓冲风险
  ↓
若形成低级别买点，生成加仓草案
  ↓
若趋势走出来，进入趋势持有 + 做T
  ↓
若背驰、三卖或路径失败，减仓 / 退出 / 锁定
  ↓
盘后复盘，更新个股作战档案
```

系统管理的是一段走势，不是预测明天涨跌。

生命周期阶段建议：

| 阶段 | 含义 | 系统重点 |
|---|---|---|
| `watching` | 观察，未建仓 | 等待大周期任务清晰 |
| `entry_probe` | 试探建仓 | 小仓试错，确认结构是否有效 |
| `entry_validation` | 建仓后验证 | 看回踩、承接、低级别买点 |
| `add_position_confirm` | 加仓确认 | 买点成立后生成加仓草案 |
| `trend_holding` | 趋势持有 | 不被小级别波动洗出，T0 降成本 |
| `distribution_or_divergence` | 高位分歧 / 背驰 | 锁利、减仓、警惕趋势结束 |
| `defense_t0` | 防守做T | 降低成本，减少结构失败亏损 |
| `exit_confirm` | 退出确认 | 三卖、反抽不过、路径失败 |
| `lockdown` | 停止操作 | 风控触发，不再新增风险 |

京东方示例：

```text
前天：试探建仓
昨天：开始做T，降低成本并缓冲风险
当前：建仓后验证期，等待 5分钟三买是否成立

上行路径：
  如果上涨后回踩不破，形成 5分钟三买，
  则大周期路径得到确认，生成加仓草案。

下行路径：
  如果跌回中枢，说明建仓路径失败或需要重新震荡，
  此时 T0 的作用是降低亏损，不再盲目加仓；
  若反抽不过，则进入防守 / 退出路径。

趋势路径：
  如果 5分钟三买成立并推动 30分钟向上一笔延续，
  则进入趋势持有阶段，系统继续用 T0 降成本、用路径引擎判断背驰和卖点。
```

这类持仓的状态不是“买入后等待涨跌”，而是：

```json
{
  "lifecycle_stage": "entry_validation",
  "major_task": "5m_third_buy_attempt",
  "position_intent": "build_position",
  "t0_role": "defense_and_cost_reduction",
  "attack_plan": "5m三买成立后生成加仓草案",
  "defense_plan": "跌回中枢后停止进攻，反抽不过则退出或减仓",
  "next_focus": "5分钟回踩是否不破中枢上沿"
}
```

这就是“大周期版本 T0”的核心：用路径管理一只票的完整生命周期。

## 3. 两套状态机

### 3.1 T0 Intraday State Machine

T0 是 1m / 5m 的小周期状态机。

目标：

- 盘中做 T
- 降成本
- 锁利润
- 纸盘验证信号质量

输入：

- 当前价
- 5m 中枢 `ZD / ZG`
- 最近 1m K 线
- 1m 顶/底分型
- 5m ATR
- `bi_strength_ratio`
- 摩擦成本
- T+1 可用数量

输出：

- `IDLE`
- `POSITION_LONG`
- `POSITION_SHORT`
- `LOCKDOWN`
- `BUY_LONG`
- `SELL_LONG`
- `SELL_SHORT`
- `BUY_SHORT`
- `STOP_LONG`
- `STOP_SHORT`
- `SWEEP_LONG`
- `SWEEP_SHORT`

原则：

- T0 由确定性代码控制，不由 AI 控制
- AI 只能解释 T0 触发含义，不能生成 T0 信号
- 第一阶段只进纸盘，不下真实单

### 3.2 Position Path Engine

持仓路径引擎是 5m / 30m / 日线 / 周线的大周期状态机。

目标：

- 判断当前走势正在完成什么结构
- 推演买卖点如何转化
- 给持仓、加仓、减仓、止损生成动作草案
- 给 T0 提供战略背景

输入：

- 周线 / 日线 / 30m / 5m CZSC 结构
- 当前价与中枢位置
- 当前笔和未完成笔
- 压力支撑簇
- 持仓成本
- 行业/市场背景
- 近期问答与交易事件

输出示例：

```json
{
  "major_task": "daily_third_buy_attempt",
  "active_level": "30m",
  "confirm_level": "5m",
  "current_phase": "pullback_confirming",
  "success_path": "5m三买成立，日线三买概率提升",
  "failure_path": "跌回中枢，三买失败，转防守",
  "next_trigger": "等待5m底分型和回踩不破",
  "draft_action": "PREPARE_ADD_ON_CONFIRM"
}
```

原则：

- 它不只列完全分类，而是判断当前最可能完成哪条路径
- 它必须表达买卖点转化
- 它给动作草案，不直接下真实单

## 4. 缠论路径任务类型

第一版先覆盖这些任务：

| 任务类型 | 含义 | 典型下一步 |
|---|---|---|
| `center_inside_selection` | 中枢内震荡选择方向 | 等离开段 |
| `center_breakout` | 向上离开中枢 | 看这一笔到哪里，等回拉 |
| `center_breakdown` | 向下离开中枢 | 看支撑与反抽 |
| `third_buy_attempt` | 三买尝试 | 看回踩不破 |
| `third_sell_risk` | 三卖风险 | 看反抽不过 |
| `class_2_buy_attempt` | 类二买尝试 | 看下跌笔衰竭与低级别买点 |
| `class_2_sell_risk` | 类二卖风险 | 看上涨笔衰竭与低级别卖点 |
| `divergence_ending` | 背驰终结 | 看反向一笔是否成立 |
| `center_expansion` | 中枢扩展 | 震荡级别升级 |
| `level_upgrade` | 级别升级 | 低级别结构演化为高级别结构 |

## 5. 买卖点转化表

| 当前尝试 | 成功后 | 失败后 |
|---|---|---|
| 1买 | 形成反向一笔，可能成为高级别类2买起点 | 继续下跌，等待新背驰 |
| 2买 | 上涨一笔延续，确认低点有效 | 跌破1买低点，转弱 |
| 3买 | 离开中枢确认，上涨趋势延续 | 跌回中枢，三买失败，可能转中枢扩展 |
| 1卖 | 形成下跌一笔，趋势减弱 | 继续新高，卖点失败 |
| 2卖 | 反弹无力，确认高点有效 | 突破前高，转强 |
| 3卖 | 跌破中枢确认，下跌延续 | 拉回中枢，三卖失败，回到震荡 |

关键是：右侧 AI 不再说“上破看强，下破看弱”这种泛泛话，而是说：

> 现在是 5m 三买尝试。成功是日线三买概率提升；失败不是简单转弱，而是跌回中枢，可能升级成中枢扩展，或者反抽不过后转 5m 三卖。

## 6. 个股 AI 作战档案

个股 AI 不是聊天记忆，而是每只股票的长期作战档案。

它记录这只票的“走势生命史”：

- 结构事件
- 买卖点事件
- 路径转化事件
- T0 纸盘事件
- 用户交易事件
- 问答事件
- 盘后复盘验证事件

### 6.1 参考架构

不手搓“一个 memory 表 + prompt 总结”，参考成熟模式：

- SmartEDC-AI project-assistant：统一 AI facade、任务节点编排、只读工具、trace 与上下文预算治理
- Event Sourcing：所有关键变化记录为事件，可回放、可审计
- LLM 长期记忆分层：semantic / episodic / procedural
- RAG：回答时只检索相关记忆，不全量塞 prompt
- QuantConnect Algorithm Framework：信号、组合、风控、执行分层
- FIX ExecutionReport：交易执行必须是状态变化，不是自然语言直接动作

SmartEDC-AI 最值得借鉴的不是具体业务代码，而是边界：

- AI 通过统一入口进入系统，不在各处散落 prompt 和工具调用
- AI 编排只读优先，不能绕过业务权限写数据
- 任务节点负责加载事实、检索记忆、控制预算、输出来源
- 聊天历史不是长期记忆；长期记忆来自事件、复盘和验证结果
- AI 是辅助判断层，不是独立业务主体

映射到 CT-OS：

```text
stock-assistant facade
  -> authorize_stock_context
  -> check_ai_feature
  -> route_intent
  -> plan_data_access
  -> load_stock_context
  -> load_position_path_state
  -> load_t0_state
  -> retrieve_stock_memory
  -> guard_context_budget
  -> stream_answer
  -> write_context_trace
  -> emit_sources
```

第一阶段的 `stock-assistant` 必须只读：

- 可以读 K 线、CZSC、T0 状态、路径状态、持仓、纸盘、历史问答
- 可以生成解释、动作草案、复盘摘要
- 可以写入 AI trace、问答事件、复盘事件
- 不能直接写真实交易
- 不能直接改状态机
- 不能直接改持仓
- 不能执行真实委托

### 6.2 记忆分层

| 类型 | 内容 | 示例 |
|---|---|---|
| Semantic | 稳定事实 | 这只票重要压力位、成本、长期中枢 |
| Episodic | 曾经发生的事 | 5m 三买失败后跌回中枢 |
| Procedural | 对这只票的操作经验 | 第一次冲压力不追，等回踩确认 |

```text
stock_events
```

### 6.4 AI 多任务编排与自我学习边界

这里的“AI 自我进化”不能理解成 AI 自己改代码、改策略或绕过风控。它应该是可审计的学习闭环：

```text
盘中事件 / 用户交易 / T0 纸盘 / 路径转化
        │
        ▼
stock_events 事件沉淀
        │
        ▼
盘后 memory review
        │
        ▼
stock_profiles 更新个股画像
        │
        ▼
下一次问答 / 推演 / 动作草案读取这只票的历史经验
```

多任务 AI 不是一个模型同时乱跑，而是不同任务有不同职责：

| 任务 | 触发 | 作用 | 是否可写业务数据 |
|---|---|---|---|
| `intraday_chat` | 用户盘中提问 | 结合当前价、1m/5m、路径状态短答 | 否 |
| `path_review` | 盘后或手动复盘 | 验证昨日路径是否兑现 | 只写 review 事件 |
| `memory_distill` | 事件累计到阈值 | 更新个股画像和经验摘要 | 只写 profile |
| `t0_paper_review` | 收盘后 | 评估纸盘胜率、滑点、回撤 | 只写纸盘统计 |
| `trade_intent_parser` | 用户说买卖语义 | 生成待确认交易草案 | 否，确认后另走交易接口 |

每次 AI 调用都要有：

- `request_id`
- `symbol`
- `intent`
- `loaded_context_keys`
- `source_event_ids`
- `prompt_token_budget`
- `model`
- `response_summary`
- `risk_flags`

这让系统知道 AI 为什么这么说，也方便以后评估“这只票的 AI 是否越来越懂它”。

## 7. 右侧 LLM 的新职责

右侧 LLM 未来是“个股专属 AI 助手”，但它不直接控制状态机。

它的职责：

1. 解释当前结构路径
2. 结合个股历史说明这只票以前类似位置怎么走
3. 结合用户持仓说明现在最该防什么
4. 把状态机信号翻译成盘中人话
5. 盘后复盘并写入个股作战档案

它不做：

- 不直接生成 T0 信号
- 不直接改状态机
- 不直接下真实交易委托
- 不把聊天印象当事实

## 8. UI 展示方案

### 8.1 Watch Card

卡片只回答一件事：

> 现在有没有动作窗口？

显示内容：

- 当前价格
- 持仓成本和盈亏
- T0 状态角标
- 当前路径一句话
- 中枢区间滑块
- 数据质量

示例：

```text
瑞芯微
193.80  -4.02%

接近5分钟下沿，等1分钟底分型
ZD 192.60 ━●━━━━ ZG 200.96
T0 等待 · 纸盘
```

触发后：

```text
瑞芯微
192.90

1分钟底分型确认，纸盘低吸
T0 正T · 今日 +0.00
```

锁定后：

```text
瑞芯微
188.20

跌破结构止损，今日锁定
T0 锁定
```

### 8.2 WatchBoard Drawer

右侧 Drawer 分三块：

1. **路径状态**
   - 大周期任务
   - 当前阶段
   - 成功路径
   - 失败路径
   - 下一触发

2. **T0 做T状态**
   - 状态
   - 5m 中枢
   - 当前价距离
   - 1m 分型
   - 笔力度
   - 摩擦空间
   - 可用 T0 数量
   - 今日纸盘收益

3. **个股 AI 解释**
   - 当前路径的人话解释
   - 历史相似事件
   - 用户行为提醒
   - 盘后验证结果

### 8.3 动作流水

Drawer 里必须显示动作流水：

```text
10:12 进入 ZD 触发区，等待 1m 底分型
10:18 1m 底分型确认，纸盘 BUY_LONG 500股 @193.20
10:44 回到 ZG，纸盘 SELL_LONG，收益 +320
14:55 扫尾完成
```

这比“关注某价格”更有意义，因为它展示的是连续动作。

## 9. 功能任务拆分

### P0：T0 纸盘做T教练

目标：确定性 T0 跑稳，前端看得懂。

- [ ] T0 输入统一：当前价、5m `ZD/ZG`、1m K 线、数据质量
- [ ] 数据不足时禁止触发纸盘，只返回观察状态
- [ ] 5m 中枢边界触发：接近 ZD / ZG
- [ ] 1m 顶/底分型确认
- [ ] `is_grid_viable()` 摩擦过滤
- [ ] `bi_strength_ratio` 笔力度过滤
- [ ] 首次触碰 ZD 减半
- [ ] 所有触发写入 paper fills
- [ ] 14:55 强制扫尾
- [ ] LOCKDOWN 日内锁定
- [ ] Watch Card 显示 T0 状态
- [ ] Drawer 显示 T0 动态看板和动作流水

### P1：资金管理

目标：信号不能脱离仓位和风险。

- [ ] T+1 可用股数计算
- [ ] 单票 T0 数量上限
- [ ] A 股 100 股整手向下取整
- [ ] 日内亏损上限
- [ ] 连续止损锁定
- [ ] 纸盘日报

### P2：持仓路径引擎

目标：大周期版本的 T0，判断持仓路径。

## 10. 当前优先级建议

第一批只做：

1. P0 T0 纸盘做T教练
2. P2 持仓路径引擎的最小版本
3. UI：卡片状态 + Drawer 动态看板

不要第一批做：

- 真正自动下单
- 复杂向量记忆
- AI gear 控制状态机
- 大量 UI 重构

原因：

- T0 和持仓路径引擎必须先跑出可验证结果
- 个股 AI 没有事件事实源，就只能记聊天印象
- 自动交易必须建立在纸盘胜率、回撤、风控都过关之后

## 11. 成功标准

第一阶段完成后，系统应该能做到：

- 卡片清楚显示当前是等待、接近、确认、纸盘触发还是锁定
- Drawer 能解释状态机为什么没有触发或为什么触发
- AI 能把状态机和大周期路径讲成人话
- 每次纸盘动作都有事件记录和后续验证
- 用户能看到这只票接下来最可能完成什么结构，而不是只看到“关注压力支撑”

最终目标：

> CT-OS 从“会解释走势的交易教练”，升级为“有记忆、有路径、有风控、有纸盘验证的受控交易机器人前置系统”。
