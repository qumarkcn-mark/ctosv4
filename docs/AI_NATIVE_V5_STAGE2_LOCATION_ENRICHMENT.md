# AI Native V5 第二步位置增强设计草案

本文记录当前关于 V5 推演链路与“压力/支撑位置增强”的产品和工程共识。

核心目标不是给 AI 更多点位，也不是把轻纺城案例固化成模板，而是让第二步在第一步方向推演的基础上，补充“当前位置与当前走势最相关的少量多级别位置事实”，帮助 AI 把结构方向落成可观察的确认、失败和分歧路径。

## 1. 现有 V5 推演架构

当前 V5 主链路以 CZSC snapshot 为唯一结构来源：

```text
CZSC snapshots
-> structure_context_service 构造 structure facts
-> DeepSeek Pro Think full reasoning
-> 保存 full_reasoning_text
-> Think panel summary JSON
-> 保存 ai_structure_contexts.reasoning_json / coach_summary
-> Radar panel / Chat / Reminder candidates
```

现有设计的两步不是为了重复推演，而是为了分工：

```text
第一步：结构方向推演
  回答：现在走势在干什么，主线方向是什么，可能如何生长。

第二步：位置与触发增强
  回答：如果第一步方向成立，哪些位置是眼前确认、结构失败、下一分歧的观察区。
```

因此，第二步不能绕过第一步重新判断方向，也不能只拿压力位包装一遍。它应该读取第一步推演原文或摘要，在该方向基础上补充位置、活跃度和合力解释。

## 2. 这次讨论形成的关键产品判断

### 2.1 缠论给方向，位置事实给合力冲突区

股票走势是多方合力结果。某些历史压力/支撑区会产生震荡，是因为：

- 一部分资金认为已经有利润，选择兑现。
- 一部分资金认为走势启动，选择跟随或等待承接。
- 双方在关键位置反复交换筹码，容易形成新中枢、冲高回落、压力转支撑或支撑转压力。

所以第二步不是回答“压力位是多少”，而是回答：

```text
这一笔可能在哪里进入分歧？
分歧会以什么低级别结构表现出来？
什么叫消化成功？
什么叫失败？
确认之后下一段才该看哪里？
```

### 2.2 第二步不是“级别选择器”

讨论中反复确认：不能把 `main_level`、`trigger_level`、`candidate_trigger_levels` 作为第二步输入的指令字段。

原因是：只要我们告诉 AI “看 30 分钟，再看 5 分钟”，即使写成候选，也已经暗示 AI 的判断方向。这样第二步会变成选择题，失去让 AI 基于结构事实自行判断的价值。

第二步应该给：

- 第一阶段自然语言推演结果。
- 当前价格与走势事实。
- 经过当前位置和当前走势筛选后的少量多级别位置事实。
- 活跃度、量能等辅助事实。

第二步不应该给：

- 固定 `main_level`。
- 固定 `trigger_level`。
- 候选触发级别列表。
- 任务类型枚举，例如 `daily_third_buy_candidate`。
- 压力/支撑梯队。
- 已经排序好的 `primary_gate / secondary_gate`。

### 2.3 第二步也不是“结构任务选择题”

不能把结构任务写死成枚举让 AI 选择，例如：

```text
daily_third_buy_candidate
daily_second_buy_like_candidate
center_breakout_pullback
trend_extension
```

这些标签可以作为人类讨论语言，但不能作为第二步 prompt 的候选项。第二步应该让 AI 用自己的语言概括：

```text
当前走势正在尝试完成什么结构任务？
这个任务还缺什么结构确认？
哪些位置影响眼前节奏？
哪些位置影响结构任务是否成立？
确认后下一段在哪里进入分歧？
失败后结构怎样演化？
```

例如轻纺城案例中，AI 可以自己表达为“正在尝试完成大级别出中枢后的回拉确认，进一步可能关系到日线三买雏形能否成立”。这不应由输入字段直接规定。

## 3. 第二步输入原则

### 3.1 多级别，但每个级别只给少量相关位置

需要给 AI 多级别位置事实，但不能每个级别给很多压力区间。

正确原则是：

```text
多级别事实
+ 当前价格位置筛选
+ 当前走势阶段筛选
+ 第一阶段方向筛选
-> 少量 selected_location_facts
```

每个位置应该说明：

- 区间。
- 该区间背后有哪些级别角色。
- 为什么它与当前价格和当前走势相关。
- 它可能影响眼前节奏、结构健康，还是确认后的下一分歧。

### 3.2 多级别共振要合并，而不是重复罗列

如果日线和 30 分钟的压力区几乎重合，不要给两条让 AI 自己在文本里打架，而要合并成一个位置事实：

```json
{
  "zone": [4.4268, 4.499],
  "roles_by_level": [
    {"level": "day", "role": "historical_pressure_cluster", "hit_count": 2},
    {"level": "30", "role": "historical_pressure_cluster", "hit_count": 3}
  ],
  "selection_reason": "当前若重新转强，该区间是日线与30分钟共振的上方分歧区"
}
```

这样 AI 能知道这里是多级别共振位置，但不会被压力位列表淹没。

### 3.3 位置事实只解释“为什么被选中”，不替 AI 排序

`selection_reason` 可以解释这个位置为什么被提供给 AI，但不能写成命令式结论。

可以写：

```text
当前价附近，可能影响眼前止跌或继续回落。
```

不应该写：

```text
这是第一观察区，必须优先看这里。
```

## 4. 建议的第二步输入契约

下面是建议输入形态。它不包含 `main_level`、`trigger_level` 或任务类型枚举。

```json
{

    "summary": "第一阶段自然语言摘要，可选；不能包含强制级别或任务枚举"
  },
  "current_market_facts": {
    "symbol": "sh.600790",
    "price": 4.38,
    "recent_behavior": "冲高后回落，短线兑现明显",
    "activity_summary": "冲高后量能回落，仍有活跃痕迹"
  },
  "selected_location_facts": [
    {
      "id": "L1",
      "zone": [4.3053, 4.3747],
      "distance_from_price_pct": -0.9,
      "roles_by_level": [
        {"level": "5", "role": "recent_support_cluster", "hit_count": 5}

      "selection_reason": "当前价附近，可能影响眼前止跌或继续回落"

      "selection_reason": "若眼前承接失败，可能影响出中枢后回拉是否仍健康"
```

## 5. 第二步 prompt 草案

```text
你是 CT-OS 第二阶段结构增强教练。

第一阶段已经给出自然语言结构推演。你的任务不是重新做第一阶段推演，也不是从预设类型中选择任务。

下面提供：
- 第一阶段推演原文或摘要；
- 当前价格、走势和活跃度事实；
- 根据当前位置和当前走势筛选出的少量多级别位置事实。

请你自己判断：
1. 当前走势正在尝试完成什么结构任务，用自然语言表达，不要输出枚举标签。
2. 哪些位置只影响眼前节奏，哪些位置影响结构任务是否成立。
3. 哪些位置只有在确认后才成为下一分歧区。
4. 需要看到什么低级别或同级别结构，才能说明任务确认。
5. 看到什么结构，说明任务失败或延后。
6. 价格到压力/支撑区为什么容易震荡，请用资金合力解释。

规则：
- 不要机械使用某个级别。
- 不要因为输入里有某级别数据，就默认它是触发级别。
- 不要要求更多压力位列表。
- 不要把压力/支撑写成目标价。
- 不要输出买入、卖出、加仓、清仓。
- 压力/支撑只能表达为观察区、分歧区、承接区。
- 必须保留“仅供参考，不构成投资建议”。
```

## 6. 轻纺城测试教训

轻纺城测试显示：

第一轮同时给了：

- 5 分钟即时支撑 `4.3053-4.3747`
- 30 分钟结构承接 `4.1333-4.20`
- 日线/30 分钟共振压力 `4.4268-4.499`

如果不解释层级和选择原因，模型会自然选择最近的 5 分钟支撑作为第一观察区。这不一定错，但语义不够稳定。

第二轮把位置分成：

- 眼前是否止跌的即时位置。
- 如果即时承接失败，结构回拉是否仍健康的位置。
- 确认后才激活的下一分歧位置。

输出质量明显更好，但这次测试仍然有轻纺城特定表达，不能把 `30 + 5` 作为通用规则。

最终教训：

```text
第二步需要位置分层，
但不能固定级别。

第二步需要动态筛选位置，
但不能替 AI 做最终级别选择。

第二步需要多级别事实，
但不能给压力/支撑梯队。
```

## 7. 与现有代码的关系

现有 `ai_structure_reasoning.e1_dynamic_growth` 仍负责第一阶段完整推演。

当前实验脚本 `server/scripts/evaluate_next_gates.py` 已经能计算压力/支撑候选和局部 focus，但其中 `current_coach_gate_focus(structure_level='30', trigger_level='5')` 是轻纺城讨论过程中的实验形态，不适合作为通用第二步输入。

后续如果落地，应该新增独立的第二步位置选择层，例如：

```text
stage2_location_context_service
```

它的职责不是推演方向，而是：

- 读取第一阶段推演原文或摘要。
- 读取多级别 CZSC structure view。
- 读取多级别压力/支撑候选。
- 按当前价格、当前走势、第一阶段方向，筛出少量 `selected_location_facts`。
- 合并多级别重合区。
- 输出无级别指令、无任务枚举、无排序命令的位置事实。

## 8. 下一步建议

1. 用轻纺城重跑一次“无级别指令”的第二步测试。
2. 再选一个不同结构样本，例如“回调后类二买修复”语境的票，验证第二步不会套轻纺城模板。
3. 将 `selected_location_facts` 生成逻辑做成只读服务，不接主链路。
4. 建立输出质量检查：
   - 是否自行概括当前结构任务。
   - 是否没有固定级别命令。
   - 是否没有目标价/买卖词。
   - 是否区分眼前节奏、结构成立、确认后分歧。
   - 是否解释资金合力。
